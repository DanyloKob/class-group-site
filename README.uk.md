# L-23 LIFE: вебзастосунок для класної групи

[English](README.md)

Сайт однієї класної групи, зроблений насамперед під телефон: розклад, чергові та спільні фото в
одному місці замість групового чату, де все важливе відпливає за хвилину. Вхід необов'язковий: гості можуть читати Проєкти й Розклад. Вхід через Telegram-бота: учасник ділиться своїм контактом, номер
звіряється з тим, що вніс адмін, і жодного пароля пам'ятати не треба. Інтерфейс українською.

Зроблено під один клас на ~20-40 людей, тож модель даних повторює його реальний розпорядок, а не
намагається бути загальною шкільною платформою.

## Що вміє

- **Розклад.** Перегляд по днях зі смугою днів тижня й переходом через календар. Чисельник і
  знаменник, дві підгрупи (A і B) зі спільними парами на всю ширину, до чотирьох пар на день.
  Повторювані пари вносяться один раз на пару «день тижня + тип тижня», з можливістю
  перевизначити конкретну дату.
- **Чергові.** Чергування в їдальні й біля дошки як дані, а не фото паперового аркуша. Їх
  призначають на конкретні дати в редакторі місяця. Біля кожного імені редактор показує, скільки
  разів людина вже чергувала за весь час, тобто за всі місяці в базі, а не лише за відкритий, щоб
  черга розподілялася рівно. Кілька людей можуть заповнювати той самий місяць одночасно: кожна
  позначка зберігається окремо, тож ніхто не стирає імена, які щойно додав інший.
- **Проєкти.** Теми з матеріалами: PDF, PPTX (перетворюється на PDF через LibreOffice) і готові
  слайди. Читати може будь-хто, зокрема гості; учасники додають і видаляють матеріали. Кожен
  матеріал має публічну сторінку `/m/<токен>` із переглядачем і режимом презентації. Файли
  перевіряються за сигнатурою. Сторінки проєктів і матеріалів віддаються з
  `noindex, nofollow, noarchive`, тож пошуковики їх пропускають.
- **Спогади.** Стрічка тексту й фото (PNG/JPG, перевірка за сигнатурою файлу) для тих, кому
  дозволено публікувати.
- **Акаунти й ролі.** Суперадмін, адмін (староста) з окремими дозволами (призначати чергових,
  публікувати у «Спогадах») та учасник. Суперадмін реєструє учасників за номером телефону й
  ім'ям. У профілі видно аватар, якщо його вже було збережено раніше, а суперадмін має журнал
  створених і видалених записів.

Інтерфейс навмисно лишається колонкою ширини телефона на будь-якому екрані. Тема лише темна, з
одним зеленим акцентом для всіх. Сайт можна додати на головний екран телефона як застосунок.

## Стек

Next.js 16 (App Router) + TypeScript, React 19, PostgreSQL + Prisma 7, Tailwind CSS 4, Framer
Motion, Vaul, grammY (Telegram-бот), sharp, zod.

## Локальний запуск

1. Підняти Postgres (один раз):
   ```bash
   podman run -d --name classgroup-postgres -p 5432:5432 \
     -e POSTGRES_PASSWORD=devpass -e POSTGRES_DB=classgroup \
     -v classgroup-pgdata:/var/lib/postgresql/data \
     docker.io/library/postgres:16-alpine
   ```
2. `cp .env.example .env` і заповнити значення. Пояснення до кожної змінної є в самому
   `.env.example`. Токен бота можна лишити порожнім, поки не створите бота через @BotFather:
   dev-логін і решта застосунку працюють і без нього.
3. Встановити залежності, створити схему й тестових користувачів:
   ```bash
   npm install
   npx prisma migrate dev --config prisma7.config.ts
   npx prisma generate --config prisma7.config.ts
   npx prisma db seed --config prisma7.config.ts
   ```
4. `npm run dev` піднімає одразу 3 порти й процес бота:
   - `localhost:8080`: суперадмін (dev-автовхід)
   - `localhost:8090`: староста (dev-автовхід)
   - `localhost:8091`: гість (без автовходу; dev-вибір тестового учасника є у вкладці «Профіль»)

   `npm run dev:one` піднімає лише один сервер на порту 3000.

Нові змінні середовища для «Проєктів» (усі описані в `.env.example`):

- `PUBLIC_BASE_URL`: публічна адреса сайту без скісної риски, наприклад `https://2025-3.pp.ua`.
  З неї будуються публічні посилання `/m/<токен>` і кнопка «Відкрити в Microsoft».
- `MATERIALS_DIR`: каталог для файлів «Проєктів». Поза `public/`, поза `.next/standalone` і не
  всередині `UPLOADS_DIR`. У розробці порожнє значення = `storage/materials`. **У проді
  обов'язково**: без нього завантаження й сторінки матеріалів повертають
  `503 storage_not_configured`.
- `SOFFICE_PATH`: шлях до `soffice` (LibreOffice) для перетворення PPTX на PDF; типово
  `/usr/bin/soffice`. LibreOffice має бути встановлений там, де працює застосунок. Для PDF він не
  потрібен.
- `CONVERSION_TIMEOUT_MS`: необов'язково, ліміт часу одного перетворення в мс (типово 120000).
- `CONVERTER_SANDBOX`: `bwrap` (типово) запускає кожне перетворення в пісочниці bubblewrap: без
  мережі, без доступу до застосунку, його `.env` і чужих файлів. `off` вимикає пісочницю: лише для
  розробки, у проді заборонено. `BWRAP_PATH`: шлях до `bwrap`, типово `/usr/bin/bwrap`.

Файли PPTX завантажують користувачі, а готовий PDF публічний, тож перетворення має три рівні
захисту: перевірка файлу перед перетворенням (`lib/server/pptxSafety.ts` відхиляє зовнішні
зображення, медіа й OLE, посилання `file:`/`smb:`, zip-бомби), пісочниця bubblewrap і мінімальне
оточення процесу. Відхилений файл отримує статус FAILED, але оригінал можна завантажити або
відкрити в Microsoft. Якщо `bwrap` немає або він не пройшов самоперевірку, перетворення не
запускаються взагалі. Встановлення на Ubuntu 24.04, перевірка bwrap і налаштування AppArmor
описані в [README.md](README.md#pptx-conversion-sandbox).

Структура проєкту описана в [README.md](README.md#project-structure), а користувачі, ролі й
принципи продукту в `PRODUCT.md`.
